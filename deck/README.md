# 230ZA presentation deck

Built from the results already committed in this repo. Nothing here re-runs training or recomputes a result;
every number is read out of `../output/*/results.json`, `../output/sim*/table2.json`,
`../output/gan/variable_importance.json`, `../output/*/sdf_factor.csv` or the run logs.

| file | what it is |
|---|---|
| `230ZA_Presentation_Deck.pptx` | the deck, 14 slides, speaker notes on every slide |
| `230ZA_Presentation_Deck.pdf` | PDF export (rendered via Keynote on macOS) |
| `review.md` | review of the replication: our numbers vs the paper, consistency checks, disagreements, plot triage |
| `script.md` | per-slide speaker script with a timing table (10:35 of slides, 15 min including Q&A) |
| `build_deck.js` | pptxgenjs generator |
| `make_charts.py` | builds the two deck charts as PNGs from `results.json` |
| `charts/` | those two PNGs |

## Rebuilding

```bash
python3 make_charts.py          # regenerates charts/*.png from ../output/*/results.json
npm install pptxgenjs           # if node_modules is not already present
node build_deck.js              # writes 230ZA_Presentation_Deck.pptx
```

`build_deck.js` resolves the plot directory itself: it looks for `./repo/output` (script sitting next to a
clone) and then `../output` (script sitting inside the repo, which is the case here). Same for `charts/`.

## Why the charts are images, not native pptx charts

pptxgenjs can embed real OOXML charts, and the earlier version of `build_deck.js` did. Only PowerPoint
renders them: Keynote, Google Slides and most PDF converters drop them silently, leaving a blank rectangle.
Both extension slides depended on a chart, so they are now PNGs generated by `make_charts.py` in the deck
palette. Same numbers, renders everywhere.

## Rendering to PDF

There is no LibreOffice on this machine. The PDF was produced with Keynote:

```bash
open -a Keynote 230ZA_Presentation_Deck.pptx
```

then File → Export To → PDF. On a machine with LibreOffice, `soffice --headless --convert-to pdf` is the
faster route.
